# テスト手順

このファイルは **実施すべき確認の一覧**です。成功実績ではありません。実施した日付、OS、Java、ローダー、MOD バージョン、ログ、成功 / 失敗 / 未実施を `TEST_RESULTS.md` に残してください。専用の使い捨てワールドを使い、破壊操作の前にバックアップします。

## 実行コマンドと確認範囲

JDK 17 で、リポジトリのルートから実行します。

```sh
bash tests/run-core-tests.sh
python3 tests/validate-project.py
./gradlew -Ploader=forge -Pgame_tests :forge:runGameTestServer
./gradlew -Ploader=forge -Pclient_tests :forge:runClient
```

core テストは設定モデル、NBT テストは実物の Minecraft NBT に対する保存・復元を確認します。NBT テストは実物の Mojang 名 Minecraft クラスパスを `HEROBRINE_TEST_CLASSPATH` に指定し、`python3 tests/run-world-data-tests.py` で実行します。

`-Pgame_tests` は実際の Forge / Minecraft GameTest サーバーでシナリオを動かします。XML 出力先は `forge/build/gametest-results.xml`。`-Pclient_tests` は実クライアントとチート OFF の Survival 統合サーバーを使い、GUI 操作・同期・描画と PNG 取得を行います。出力先は `docs/runtime-client/` です。グラフィック表示環境、または利用可能な Xvfb が必要です。

Fabric の配布用代替ビルドと、その配布 JAR を使う実行テスト：

```sh
python3 tools/fabric_manual_build.py
python3 tools/fabric_run_gametests.py
python3 tools/fabric_run_client_smoke.py --xvfb-root /path/to/xvfb-root
```

Fabric の各実行スクリプトは `COMPATIBILITY.md` の取得済みキャッシュ・`../toolchain` 構成を使います。GameTest には upstream `fabric-gametest-api-v1` **1.2.13+1802ada577** も必要です。クライアントの `--xvfb-root` は `usr/bin/Xvfb`、`usr/bin/xdotool` と対応ライブラリを含むディレクトリです。結果は `docs/gametest-fabric-results.xml` と `docs/runtime-client-fabric/` に出力します。

GameTest のワールド処理、クライアントの GUI / 描画、モデル / NBT テストは別の確認範囲として集計します。テスト専用クラスは配布物へ混ぜません。Forge の配布用ビルドは `game_tests` / `client_tests` を付けずに行い、Fabric の実行テスト用 MOD は通常の配布 JAR と別に作成します。

## チート OFF・OP 不要の標準動作

`require-permission=false` が標準です。この節はシングルプレイ所有者向けの例外だけで通過させず、所有者ではない一般プレイヤーも対象にします。

| ID | 手順 | 合格条件 |
|---|---|---|
| P01 | 設定ファイルなしで起動し、チート OFF の Survival ワールドに参加 | `require-permission=false` が作成され、OP・チート有効化・UUID 登録なしで全カテゴリの設定を操作可能 |
| P02 | 専用サーバーへ、所有者ではない OP レベル 0・許可リスト未登録のプレイヤーで参加 | 変身・飛行・満腹度と各アクションを MOD の機能として使用可能。サーバー処理も実際に変わる |
| P03 | 全能力の ON / OFF、倍率、保存・帰還、召喚、天候・地形変更を一般プレイヤーで実行 | OP を付与せず動作。地形などの確認画面は表示され、確認後に実行可能 |
| P04 | `destructive-lightning` / `allow-player-combat` をそれぞれ `true` にして再起動し、一般プレイヤーで該当操作 | 実体のある落雷とプレイヤー対象攻撃も OP なしで実行可能。確認・PvP / チーム判定を維持 |
| P05 | 操作前後に OP 登録・権限レベル・ワールドのチート設定を比較 | OP の隠れた付与やチート設定の変更なし |
| P06 | 標準設定で能力中に deop、再接続、死亡・復活、次元移動 | OP と独立した利用を維持。個別設定と倍率を保持し、各ライフサイクルに合わせて効果を再適用 |
| P07 | 旧版の設定から `require-permission` を省略して起動 | 新しい標準の `false` として読み込み、一般プレイヤーも使用可能 |

## 保存とライフサイクル

1. 全トグルと異なる倍率、帰還地点、召喚 Mob を設定し、通常保存して再起動します。ワールドと UUID ごとの値が復元されることを確認します。
2. 死亡 / リスポーン、ネザー・エンド移動、再ログイン、サーバー終了を確認します。旧 Player オブジェクトへ効果が残らないことを確認します。
3. 同じクライアントでワールド A → B → A と切り替えます。A の能力・帰還地点・変身表示が B に混入しないことを確認します。
4. 標準設定で deop しても能力が継続することを確認します。別ケースとして `require-permission=true` に設定し、所有者でも UUID 許可リスト登録者でもないプレイヤーの OP を解除します。この場合だけ、設定を保持して飛行・透明化・速度補正などの効果を停止することを確認します。
5. 他 MOD やポーションで飛行・透明化・属性補正を与え、この MOD の ON / OFF を行います。元の状態を意図せず削除しないことを確認します。
6. 保存データの欠落・古い項目・破損した倍率・無効な UUID / 次元名をバックアップのコピー上で試します。クラッシュせず安全な既定値へ戻るか、復旧方法が明確であることを確認します。

## 権限、通信、静的解析

- 標準 `require-permission=false` では、OP レベル 0 / 1 / 2、所有者 / 非所有者、UUID 許可リスト登録 / 未登録にかかわらず全能力を操作できることを試す。チート OFF の実ワールドでも確認する。
- 任意の `require-permission=true` では、権限レベル 2 以上の OP・シングルプレイ所有者・UUID 許可リスト登録者だけが許可されることを試す。OP の取り消し、許可設定変更後の再起動も確認する。
- 制限モードで不許可となるクライアントから加工した要求を送っても、サーバーの世界や属性を変更できないことを確認する。この期待値を標準設定の非 OP に適用しない。
- 未知の操作名、未知の能力名、過長文字列、過大 / 入れ子 NBT、NaN / ±Infinity、負数、過大倍率を試し、通信スレッドやサーバーを落とさないことを確認する。
- 全体の送信頻度制限と各アクションの cooldown を超える要求を試す。拒否された要求が余分な生成・破壊・同期処理を増やさないことを確認する。
- クライアントが別の UUID、他のプレイヤー、自由な座標を指定して操作できないことをコードと通信試験の両方で確認する。
- サーバー側のメインスレッドで変更していること、ローダーの受信側が適切にキューへ積むことを確認する。
- client 専用クラスの参照、NBT 長の検査、数値境界、所有者照合、データ保存の警告を静的に調べる。
- 依存関係の解決後、実際に使った推移依存の一覧を保存し、公式アドバイザリ / 脆弱性データと照合する。接続不能の場合は照合未実施と記録する。

## 他 MOD との組合せ

キー競合、スキン変更、プレイヤー描画、シェーダー、軽量化、チャット装飾、権限 / 保護、飛行、属性を変更する MOD を対象にします。実際に導入した MOD の名前と版を記録し、単体構成との比較を行います。未試験の組合せまで互換性を一般化しないでください。
